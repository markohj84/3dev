# 3DEV AI Development Harness v1.0 Implementation Plan

**Goal:** incorporar la metodología compartida y su evidencia local sin cambiar el sitio.

**Architecture:** `.3dev/` es la fuente única por tema, los adaptadores sólo apuntan a ella y `docs/` conserva el contexto de este proyecto. No se agrega runtime.

**Tech Stack:** Markdown; scripts existentes de Astro y Node para validación.

**Spec:** [Discovery y criterios de aceptación](../../product/harness-v1-discovery.md), derivados de la solicitud explícita del usuario.

## Restricciones y decisiones de ejecución

- Sólo documentación; sin código de producto, dependencias, cambios remotos, commit, push o deploy.
- Inspeccionar el repo actual antes de editar; conservar su divergencia con `origin/main` local.
- Implementación directa con auditoría y revisión independientes. No requiere aprobación adicional para las ediciones locales ya solicitadas.
- Comprobación documental proporcional; no crear tests que sólo reflejen texto ni infraestructura de generación de reglas.

- [x] Inspeccionar estado, fuentes activas, instrucciones existentes y scripts; documentar diferencias respecto de antecedentes.
- [x] Crear AGENTS.md, CLAUDE.md y `.3dev/HARNESS.md`: verificar lectura común, workflow, roles y separación contexto/metodología.
- [x] Crear ARCHITECTURE, QUALITY, SECURITY, INTEGRATIONS y AI-AGENTS: verificar cobertura completa y autoridad por tema.
- [x] Crear cuatro plantillas: Discovery, ADR, AI Opportunity Map, delivery report; comprobar campos y referencias.
- [x] Registrar contexto, Discovery y ADR específicos; sustituir README starter por índice del proyecto.
- [x] Revisar requisitos, enlaces locales, contradicciones y alcance del diff; aplicar correcciones documentales.
- [x] Instalar únicamente estos documentos en el repo inspeccionado sin sobrescribir cambios concurrentes.
- [x] Ejecutar `npm test`, `npm run build`, `git diff --check`; reportar scripts no disponibles.
- [x] Completar informe con resultados, decisiones, limitaciones y pendientes; entregar sin commit.

## Foco de revisión

| Riesgo | Comprobación |
| --- | --- |
| Documentación vieja restaura UI/rutas anteriores | Contexto vinculado al código vigente y antecedentes marcados |
| Dos agentes usan políticas divergentes | Ambos adaptadores remiten a HARNESS; una autoridad por regla |
| Arquitectura conceptual parece implementada | Separar referencia de inventario real y demo de integración |
| Una tool elude aprobación o permisos | SECURITY exige controles fuera del modelo; contratos enlazados |
| Build aprobado se confunde con auditoría o typecheck | Registrar alcance real de cada check y los no disponibles |

## Registro de ejecución

La inspección y los documentos se preparan antes de escribir en el repositorio objetivo. La [entrega](../../product/harness-v1-delivery.md) conserva evidencia final y cualquier limitación; este plan no requiere instalar las habilidades usadas durante su preparación para operar el Harness.
